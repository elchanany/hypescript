# סוכני הפרויקט — מי עושה מה

הקצאה לפי **עלות הטעות**, לא לפי גודל המשימה. משימה שטעות בה נכשלת ברעש
(בדיקה אדומה, בילד שנופל) יכולה לרדת למודל זול. משימה שטעות בה **נכשלת בשקט**
— מילה שנעלמת מהסרטון של לקוח, סף שמכויל לא נכון, רישיון מוזיקה שגוי — נשארת
למודל החזק.

| סוכן | מודל | מתי |
|---|---|---|
| `algorithm-engineer` | **Opus** | יישור, אקוסטיקה, מיקום חיתוך, כתוביות, מנוע כוונה |
| `feature-builder` | Sonnet | רכיבים, כלי סוכן, פקודות, קטלוג — כשההחלטה כבר התקבלה |
| `test-author` | Sonnet | בדיקות רגרסיה ואינווריאנטות לקוד קיים |
| `browser-qa` | Sonnet | אימות בדפדפן החי, קונסולה, רשת, צילומים |
| `research-scout` | Sonnet | APIs, ספריות, ורישוי — לפני שמתחייבים |
| `verifier` | Haiku | tsc + בדיקות + בילד מבודד + Python. מכני |
| `continuity-keeper` | Haiku | `.ai/` ו-docs אחרי שהעבודה נחתה. מכני |

## למה החלוקה הזו

**Opus לאלגוריתמים** כי שם הכישלון שקט. שלושת הבאגים בהסרת הנשימות עברו
בדיקות ירוקות ופלט תקין לחלוטין — הם נתפסו רק ממדידת התפלגות הפערים בהקלטה
אמיתית. אין בדיקה שתופסת "הסף שגוי ב-8dB".

**Sonnet למימוש** כי המפרט כבר קיים והכישלון רועש: TypeScript לא מתקמפל,
בדיקה נופלת, הרכיב לא מרונדר.

**Haiku לאימות ולתיעוד** כי אלה פקודות קבועות ורישום עובדות. `verifier` לא
מחליט כלום — הוא מריץ ארבע פקודות ומדווח מספרים.

## כללי עבודה במקביל

הרפו הזה מריץ כמה סוכנים בו-זמנית. שני כשלים אמיתיים כבר קרו: ארבעה בילדים
נלחמו על אותה `.next` ונתקעו לשעות, ואז סוכן שניקה הרג בילד **חי** של עמית.

1. בילד — תמיד `node scripts/agent-build.mjs --name=<נושא>`, לעולם לא `npm run build`.
2. `--list` לפני הריגת כל תהליך. מה שברשימה — חי.
3. `git add` ממוקד לנתיבים שלך. לעולם לא `-A`.
4. mtime אינו הוכחה שסשן מת.

הפרוטוקול המלא ב-[AGENTS.md](../../AGENTS.md).

## שרשרת אופיינית

```
research-scout   → האם בכלל אפשר, ובאיזה רישיון
algorithm-engineer / feature-builder → מימוש
test-author      → בדיקות שנכשלות אם הבאג חוזר
verifier         → tsc · vitest · build · python
browser-qa       → אימות חי (רק אם יש שינוי נראה)
continuity-keeper → .ai/ + docs + graphify
```

לשינוי מכני קטן אפשר לדלג ישר ל-`verifier`. לשינוי אלגוריתמי — אף פעם לא
לדלג על `test-author`.
